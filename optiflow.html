Orbis Mind/OptiFlow
Active Research runtime · Go · MIT

Make it faster.
Prove it's still correct.

OptiFlow is an adaptive compiler and self-optimizing runtime for AI workflow graphs. It automatically discovers, measures, and verifies better execution strategies — and a plan that is faster but changes results is rejected. Latency never overrides correctness.

The adaptation loop GitHub ↗
The research question. Can an AI runtime continuously improve the execution of complex AI workloads under changing conditions while preserving correctness, quality, and reliability?
Positioning

Whole-workflow optimization

OptiFlow optimizes the execution strategy of an operation graph — scheduling, concurrency, caching, redundancy elimination — independent of which backend runs the operations.

What it does

  • Takes a declarative spec of an AI workload — a graph of operations wired by data dependencies.
  • Discovers candidate execution plans and benchmarks each against a baseline.
  • Verifies correctness before adoption — equivalence, schema, and quality checks.
  • Adopts, rejects, or rolls back with a recorded decision history and an explanation.

What it is not

  • Not an LLM gateway or model router.
  • Not a prompt optimizer.
  • Not a generic agent framework.
  • Not a GPU-kernel compiler.
Architecture

Six components, one adaptation loop

Each component is independently testable; together they form a closed loop from workload to verified adoption.

A

Workload Intelligence · pkg/workload · graph · profile

Parse & validate specs, build the DAG, and find bottlenecks and optimization opportunities.

B

Adaptive Execution Graph + Runtime · pkg/graph · runtime

Dependency-aware concurrent scheduling with retries, timeouts, cancellation, and checkpoints. Every candidate plan still honors the DAG.

C

Optimization Search · pkg/optimize

Generate candidate execution plans from a workload profile — eliminate redundancy, parallelize, re-cache.

D

Experimental Execution · pkg/experiment

Controlled, repeated benchmarking: p50/p95/p99, resource cost, overhead, and regression detection.

E

Correctness Verification · pkg/verify

Deterministic equivalence, schema / constraint, and quality checks. A plan must pass before it can ever be adopted.

F

Continuous Adaptation · pkg/adapt

A deterministic policy with decision history, rollback, and explanations — adopt, reject, or revert, always auditable.

By example

Every speedup is proven, or it's dropped

optiflow bench examples/rag_pipeline.json — each + plan was both measured faster and verified to produce outputs equivalent to the baseline.

optiflow bench — rag_pipeline.json
  PLAN             p50(ms)   p95(ms)   p99(ms)   thrpt/s   speedup  DECISION
  baseline          223.80    229.73    229.73      4.47     1.00x  reference
+ eliminate         124.28    126.31    126.31      8.05     1.80x  accepted: verified correct and 44.5% faster
+ parallel          125.19    126.56    126.56      8.04     1.79x  accepted: verified correct and 44.1% faster
A plan that is faster but changes results is rejected — latency never overrides correctness.
Quick start

Run the loop locally

Requires Go 1.26+. The Docker image build runs the full test suite.

build & explore
make build                 # builds bin/optiflow
./bin/optiflow validate examples/rag_pipeline.json
./bin/optiflow graph    examples/rag_pipeline.json
./bin/optiflow profile  examples/rag_pipeline.json
optimize · verify · adopt
./bin/optiflow optimize examples/rag_pipeline.json
./bin/optiflow bench    examples/rag_pipeline.json  # measured + verified
./bin/optiflow adapt    examples/rag_pipeline.json  # adopt the best plan
./bin/optiflow explain  examples/rag_pipeline.json  # why each plan won/lost
